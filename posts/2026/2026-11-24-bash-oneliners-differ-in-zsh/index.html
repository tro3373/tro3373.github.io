bash のつもりの 1 行が zsh で変わる 6 か所

2026-11-24 ·  2026-11-24 · 8 分 · 1501 文字

結論#

  • zsh は sh (POSIX のシェル) との互換を既定にしていない。bash で書いた 1 行を zsh が読むと、エラーにならずに結果だけが変わるか、コマンドが走らずに止まる
  • 結果が変わる: 引用符の無い変数を 1 語のまま渡す。空の変数をパターンにした置換は、各文字の前に置換文字列を挿す。PIPESTATUS と BASH_REMATCH は空のまま
  • 止まる: 何にも一致しない glob は no matches found でコマンドごと止まる。引数付きの $EDITOR は 127。path に代入すると、以後のコマンドがすべて 127
  • # は bash より zsh の方が多く残す。bash は語の先頭の # から行末までをコメントとして捨てるが、zsh は対話入力の # をコメントにせず、引数として渡す
  • 起きるのは zsh が読むときだけ。1 行目に #!/usr/bin/env bash を書いたスクリプトと、bash -c '...' で包んだ 1 行は bash が読むので起きない。bash 前提の処理はどちらかで渡す

以下は zsh 5.9.2 / GNU bash 5.3.20 / fzf 0.74.4 / Linux x86_64 で実測した。 zsh は -f (.zshrc などの起動ファイルを読まない) で起動し、設定に左右されない既定の挙動を測った。

前提: bash のつもりの 1 行を zsh が読む経路#

ログインシェル ($SHELL) が zsh の環境では、次の経路で 1 行を zsh が読む。 対話シェルは、プロンプトを出して人の入力を 1 行ずつ読むシェル。非対話は、-c に渡した文字列やスクリプトを読んで終わるシェル。

  • 端末に手で打つ。手順書や README の行をコピーして貼る (対話シェル)
  • tmux send-keys で、tmux のペインで動いているログインシェルにキー入力として打ち込む (対話シェル)
  • fzf の bind (キーに割り当てたコマンド) を、fzf が $SHELL -c '<1 行>' で起動する (非対話)。fzf は、標準入力から受け取った行を一覧に出し、人が絞り込んで選んだ行を出力するコマンド
  • コーディングエージェントのシェル実行ツールが zsh で動く環境で、エージェントが bash のつもりで書いた 1 行を実行する (非対話)

1 行目に #!/usr/bin/env bash (shebang) を書いたスクリプトを実行したときと、bash -c '...' で包んだときは bash が読むので、以下の違いは起きない。

違いの元は、zsh の 3 つのオプション (setopt で切り替えるシェルの挙動) の既定値にある。

オプションzsh の既定bash の既定の挙動
SH_WORD_SPLIToff: 引用符の無い変数を分けない空白などで分ける
NOMATCHon: 何にも一致しない glob をエラーにする文字列のまま渡す
INTERACTIVE_COMMENTSoff: 対話入力の # をコメントにしないコメントにする

setopt には小文字で書いても通る (setopt sh_word_split)。 違いを確かめるときは、同じ 1 行を bash -c '...' と zsh -fc '...' に渡して見比べる。

引用符の無い変数を単語に分けない#

bash は、引用符で囲んでいない $v を展開した後、IFS の文字 (既定は空白・タブ・改行) で複数の語 (コマンドの引数) に分ける。これを単語分割 (word splitting) と呼ぶ。 zsh は SH_WORD_SPLIT が既定で off で、$v を 1 語のまま渡す。

bash -c 'v="a b c"; for x in $v; do echo "[$x]"; done'
zsh -fc 'v="a b c"; for x in $v; do echo "[$x]"; done'
bash -c 'v="a b c"; set -- $v; echo argc=$#'
zsh -fc 'v="a b c"; set -- $v; echo argc=$#'
[a]
[b]
[c]
[a b c]
argc=3
argc=1

zsh で分けるときは、展開ごとに ${=v} と書くか、setopt sh_word_split でシェル全体を bash に寄せる。 元から複数の値なら、文字列でなく配列 ids=(a b c) で持つ。zsh の配列の $ids は要素ごとに渡る。

zsh -fc 'v="a b c"; for x in ${=v}; do echo "[$x]"; done'
zsh -fc 'setopt sh_word_split; v="a b c"; for x in $v; do echo "[$x]"; done'
zsh -fc 'ids=(a b c); for x in $ids; do echo "[$x]"; done'
[a]
[b]
[c]
[a]
[b]
[c]
[a]
[b]
[c]
  • PITFALL: エラーにならない。1 語のまま渡っても後ろのコマンドは失敗せずに空振りすることが多く、ループが 1 回で終わったり、後ろのコマンドが別の理由で失敗したように見えたりする

引数付きの $EDITOR は 127 で落ちる#

EDITOR="code --wait" や EDITOR="nvim -u NONE" のように、引数を含めた値を bash 前提で $EDITOR file と展開すると、zsh は値全体を 1 つのコマンド名として探し、終了コード 127 (command not found) で落ちる。 EDITOR=nvim のように 1 語の値では起きないので、書いた人の手元では再現しないことがある。

下では、引数付きの値の代わりに printf ed:%s\n を EDITOR に入れ、渡ったファイル名を表示させる。

EDITOR='printf ed:%s\n' bash -c '${EDITOR:-nvim} /tmp/x.md'; echo "rc=$?"
EDITOR='printf ed:%s\n' zsh -fc '${EDITOR:-nvim} /tmp/x.md'; echo "rc=$?"
ed:/tmp/x.md
rc=0
zsh:1: command not found: printf ed:%s\n
rc=127

プログラムやワンライナーからエディタを起動するときは、展開を sh に任せ、ファイル名は引数で渡す。 sh (POSIX のシェル) は bash と同じく、引用符の無い $EDITOR を語に分けるので、呼び出し元のシェルが zsh でも printf と ed:%s\n の 2 語になる。 sh -c '<スクリプト>' a b では、a が $0、b が $1 になる。zsh の上で分けるなら ${=EDITOR} と書く。

EDITOR='printf ed:%s\n' zsh -fc 'sh -c '\''${EDITOR:-nvim} "$1"'\'' sh /tmp/x.md'
ed:/tmp/x.md

語の先頭の = はコマンドのパスに置き換わる#

変数ではないが、zsh が引数を bash と違う形に書き換える例がもう 1 つある。 zsh は語の先頭の =word を、word という名前のコマンドのパスに置き換える (EQUALS オプション)。 echo =ls は /usr/bin/ls を出す。オプションの値を空白で区切って -t =a と渡すと、=a が語の先頭になるので、a というコマンドが無ければエラーで止まり、コマンドは実行されない。= で始まる引数は引用する。

zsh -fc 'echo =ls'
zsh -fc 'echo -t =a'; echo "rc=$?"
zsh -fc 'echo -t "=a"'
/usr/bin/ls
zsh:1: a not found
rc=1
-t =a

fzf の bind は $SHELL -c で走る#

fzf は execute / preview / reload などの bind のコマンドを、--with-shell オプションの既定値の $SHELL -c で起動する。 ログインシェルが zsh の利用者では、bind の中の ${EDITOR} が 1 語のまま渡り、127 で失敗する。fzf の一覧にはエラーが出ない。 bind を書いた人の手元のシェルが bash か、EDITOR=nvim なら再現しない。

# ctrl-e で選んだ行をエディタで開く。SHELL が zsh だと 127 で失敗する
echo /tmp/x.md | fzf --bind 'ctrl-e:execute(${EDITOR:-nvim} {})'

# 中身を sh に解釈させ、選んだ行は引数で渡す
echo /tmp/x.md | fzf --bind 'ctrl-e:execute(sh -c '\''${EDITOR:-nvim} "$1"'\'' sh {})'

{} は、fzf が選んだ行に置き換える (引用符を付けて埋めるので、"{}" と自分で囲まない。 スクリプトから呼ぶ fzf が返す値と終了コード )。 fzf は端末が無いと起動しないので、util-linux の script で疑似端末 (プログラムからは本物の端末に見える仮想の端末) を作り、EDITOR='printf ed:%s\n' を入れて、ctrl-e のキー (0x05) を送って測った。端末に出た行のうち、結果の行だけを抜き出す。

SHELL=bash, 1 つ目の bind:  ed:/tmp/x.md
SHELL=zsh,  1 つ目の bind:  zsh:1: command not found: printf ed:%s\n
SHELL=zsh,  2 つ目の bind:  ed:/tmp/x.md
  • PITFALL: --with-shell 'sh -c' で bind 全体を sh に変える手もあるが、利用者が FZF_DEFAULT_OPTS (fzf が毎回読む既定の引数を入れる環境変数) に書いた bind まで sh で走る

何にも一致しない glob はコマンドごと止まる#

glob は * ? [...] を含む語で、シェルが一致するファイル名の並びに置き換える。zsh では (...) も glob の記号 (パターンのまとまりを作る) になる。 何にも一致しないとき、bash は語をそのまま渡す。zsh は NOMATCH が既定で on なので、no matches found を出してそのコマンドを実行しない。 go env -w GOPRIVATE=a/*、grep --include=*.go、CLI の --model に渡すモデル名 opus[1m] のように、ファイル名のつもりでない値に * や [ が入ると当たる。

空のディレクトリで試す。

bash -c 'echo GOPRIVATE=a/*'
zsh -fc 'echo GOPRIVATE=a/*'; echo "rc=$?"
bash -c 'echo opus[1m]'
zsh -fc 'echo opus[1m]'
bash -c 'printf "[%s]\n" --include=*.go'
zsh -fc 'printf "[%s]\n" --include=*.go'
GOPRIVATE=a/*
zsh:1: no matches found: GOPRIVATE=a/*
rc=1
opus[1m]
zsh:1: no matches found: opus[1m]
[--include=*.go]
zsh:1: no matches found: --include=*.go

zsh -c の文字列とスクリプトでは、エラーの後ろのコマンドも走らない。|| の右側も走らない。

zsh -fc 'echo before; echo a/*; echo after'
zsh -fc 'echo before; echo a/* || echo fallback; echo after'
before
zsh:1: no matches found: a/*
before
zsh:1: no matches found: a/*

同じ 3 行 (echo before / echo a/* || echo fallback / echo after) をファイルに書いて zsh -f で実行しても、2 行目の no matches found で終わり、3 行目は実行しなかった。

直し方は、語か値を引用符で囲む。どちらも引用符はシェルが外すので、コマンドには同じ文字列が渡る。 zsh の setopt は、オプション名の頭に no を付けるとそのオプションを off にする。setopt nonomatch は NOMATCH を off にし、bash と同じ挙動になるが、シェル全体に効く。1 つの引数のためなら引用符で囲む方が影響が狭い。

zsh -fc "echo 'GOPRIVATE=a/*'"
zsh -fc "echo GOPRIVATE='a/*'"
zsh -fc 'setopt nonomatch; echo GOPRIVATE=a/*'
GOPRIVATE=a/*
GOPRIVATE=a/*
GOPRIVATE=a/*

tmux send-keys でログインシェルに mycmd --model opus[1m] のようなコマンドを打ち込むときは、値を bash の printf '%q' で引用してから組み立てる。 printf '%q' が出す opus\[1m\] は、zsh でも opus[1m] に戻る。

zsh -fc "echo $(printf '%q' 'opus[1m]')"
# tmux send-keys "mycmd --model $(printf '%q' 'opus[1m]')" Enter
opus[1m]

zsh -fc "printf '[%s]\n' \"GOPRIVATE='a/*'\""
[GOPRIVATE='a/*']
  • PITFALL: 起動した後の ps に出る引数 (argv) には引用符が残らないので、argv を見ても引用されていたかは分からない

bash の for は、一致が無いとパターンの文字列で 1 回回る#

bash の側にも、同じ挙動から来る罠がある。for f in dir/*.json は、一致するファイルが無いと dir/*.json という文字列で 1 回回る。 shopt -s nullglob を立てると、一致の無い glob が消えて 0 回になる。ループの中で [[ -f $f ]] || continue と弾いてもよい。

bash -c 'for f in /nonexistent/a-*.json; do echo "[$f]"; done'
bash -c 'shopt -s nullglob; for f in /nonexistent/a-*.json; do echo "[$f]"; done; echo done'
[/nonexistent/a-*.json]
done

対話入力の # はコメントにならない#

bash では、語の先頭の # から行末までがコメントになる。対話入力でも、bash -c の文字列でも、スクリプトでも同じ。 zsh は INTERACTIVE_COMMENTS が既定で off で、対話入力の行の # をコメントにしない。-c の文字列とスクリプトは、常にコメントとして読む。

対話シェルは、zsh -fi (-i で対話シェルにする) に標準入力から行を流して作る。プロンプトは stderr に出るので捨てる。

printf '%s\n' 'print -r -- a #b' | zsh -fi 2>/dev/null
zsh -fc 'print -r -- a #b'
zsh -fic 'print -r -- a #b' 2>/dev/null
printf '%s\n' 'echo start #123 end' | bash --norc -i 2>/dev/null
a #b
a
a
start

手順書や AI が出した「コマンド # 説明」の形の行を zsh の端末に貼ると、# 以降が引数として渡る。 コマンドによっては余計な引数としてエラーで止まり、止まらずにファイル名として扱うコマンドだと、意図しない対象に作用する。 コメントのつもりの部分に括弧があると、zsh では括弧も glob の記号なので、dir(1)/y がファイル名のパターンとして読まれ、前節の no matches found で止まる。

printf '%s\n' 'echo x # dir(1)/y' | zsh -fi 2>&1 | grep -ao 'zsh: .*'
zsh: no matches found: dir(1)/y

.zshrc に setopt interactivecomments を書けば、対話入力でもコメントになる。 同じ行に書いた setopt は、その行の # には効かない。次の行から効く。

printf '%s\n' 'setopt interactivecomments; print -r -- a #b' | zsh -fi 2>/dev/null
printf '%s\n' 'setopt interactivecomments' 'print -r -- a #b' | zsh -fi 2>/dev/null
a #b
a
  • PITFALL: zsh -i -c '...' で試すと、-c の文字列なのでコメントになり、再現しない (上の 3 つ目)

# で始まる引数は、引用しないと消える#

向きが逆の罠もある。bash と、zsh の -c の文字列・スクリプトでは、#123 (issue 番号) や #fff (色コード) のような # で始まる引数は、引用しないとコメントとして消える。 引数 0 個として動くので、呼ばれたコマンドは引数不足のエラー (例: accepts 1 arg(s), received 0) を出し、コマンドの仕様の問題に見える。 引数を省くと全件を対象にするコマンドでは、1 件のつもりの呼び出しが全件に作用する。

bash -c 'count() { echo "argc=$#"; }; count #2'
bash -c 'count() { echo "argc=$#"; }; count '\''#2'\'''
printf '%s\n' 'count() { echo "argc=$#"; }' 'count #2' | zsh -fi 2>/dev/null
argc=0
argc=1
argc=1

3 つ目は zsh の対話入力なので、#2 は引数として残る。 # で始まる引数は '#2' と引用する。番号を受け取るコマンドを作る側なら、# を付けない 2 で受け取れる形にしておく方が壊れにくい。

bash 専用の変数と展開は、zsh で空になるかエラーになる#

  • PIPESTATUS (パイプの各コマンドの終了コードの配列) は zsh では空で、zsh は小文字の pipestatus に入れる ( bash のパイプが返す終了コードと SIGPIPE )
  • [[ $s =~ 正規表現 ]] の一致は zsh でも真になるが、括弧で捕まえた部分を入れる配列 BASH_REMATCH は空のまま
  • ${R^^} (値を大文字にする展開) は zsh では bad substitution で落ちる。zsh では ${(U)R} と書く
bash -c 'false | true; echo "PIPESTATUS=${PIPESTATUS[*]}"'
zsh -fc 'false | true; echo "PIPESTATUS=${PIPESTATUS[*]} pipestatus=${pipestatus[*]}"'
bash -c 'line="id=42"; [[ $line =~ id=([0-9]+) ]] && echo "BASH_REMATCH[1]=${BASH_REMATCH[1]}"'
zsh -fc 'line="id=42"; [[ $line =~ id=([0-9]+) ]] && echo "BASH_REMATCH[1]=${BASH_REMATCH[1]}"'
bash -c 'R=abc; echo "${R^^}"'
zsh -fc 'R=abc; echo "${R^^}"'
zsh -fc 'R=abc; echo "${(U)R}"'
PIPESTATUS=1 0
PIPESTATUS= pipestatus=1 0
BASH_REMATCH[1]=42
BASH_REMATCH[1]=
ABC
zsh:1: bad substitution
ABC
  • PITFALL: shebang が bash のスクリプトは、実行すれば bash が読むので問題ない。source は、ファイルを新しいシェルを起動せずに今のシェルに読ませるコマンドで、shebang を見ない。zsh の端末で source すると zsh が読むので、=~ の一致が取れていないように見える。動作確認は bash script.sh か bash -c で行う

空の変数をパターンにした置換は、各文字の前に挿す#

${s//パターン/置換文字列} は、s の中のパターンをすべて置換文字列に置き換える。 パターンが空文字のとき、bash は s を変えない。zsh は各文字の前に置換文字列を挿す。

bash -c 's=abc; e=""; echo "${s//$e/*}"'
zsh -fc 's=abc; e=""; echo "${s//$e/*}"'
abc
*a*b*c

ログの中の秘密値を伏せる ${log//$secret/***} は、秘密値が空だと、zsh ではログ全体が崩れる。置換の前に、空の値を弾く。

bash -c 'log="token=abc"; secret=""; echo "${log//$secret/***}"'
zsh -fc 'log="token=abc"; secret=""; echo "${log//$secret/***}"'
token=abc
***t***o***k***e***n***=***a***b***c
  • PITFALL: 試したシェルと実行するシェルが違うと、「空でも何も起きない」のような誤った前提がコメントやコミットメッセージに残る

path に代入すると PATH が変わる#

zsh の path は、PATH と連動する配列。path に入れた値が、そのまま PATH に反映される。 bash の感覚で path=/tmp/x と一時的な変数に使うと、PATH が /tmp/x になり、以後のコマンドがすべて command not found (127) になる。

zsh -fc 'path=/tmp/x; echo "PATH=$PATH"; ls >/dev/null'; echo "rc=$?"
bash -c 'path=/tmp/x; ls >/dev/null && echo ls-ok'
zsh -fc 'dir=/tmp/x; ls >/dev/null && echo ls-ok'
PATH=/tmp/x
zsh:1: command not found: ls
rc=127
ls-ok
ls-ok

zsh で打つ 1 行では、変数名に path を使わない。

  • PITFALL: 代入した行ではなく、その後の全部のコマンドが落ちる。エラーは ls など無関係なコマンドの not found として出る
